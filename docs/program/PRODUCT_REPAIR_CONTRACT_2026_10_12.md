12 October 2026. This is the executable design for PRD-01, following the [lineage audit](MASTER_PROGRAM_LINEAGE_REVIEW_2026_10_12.md) and the [banking product contract](BANK_HPO_NAS_PRODUCT_CONTRACT.md). Seed aggregation is performed per candidate and per declared fidelity before a single tuner observation; incomplete aggregates have a prespecified failure/missing-data policy. Common tuning seeds can pair candidate comparisons. Final seeds and, where applicable, final data roles are disjoint. Record arithmetic mean and spread from raw replicates unless the declared objective specifies another scientifically appropriate statistic. No arbitrary universal seed count is claimed to guarantee precision. Deterministic fixtures use a recorded opt-out, and empirical precision is a separate design problem.

Existing schemas require versioned migration. A previous objective callable without a declared identity cannot be retroactively certified by hashing its function name. Scalar and vector studies must share evaluation roles, while vector selection returns a frozen feasible front or a prospectively declared scalar preference. Test identity and state transitions before adding each workload profile.

## Historical operations clauses

The user's waiver of separate-machine testing does not establish production capabilities. The current authority qualifies trusted supervised local research. This table is a retained disposition inventory, not a claim that these legacy features already work.

| Original clause | Current disposition / PRD-OPS check |
|---|---|

| Full snapshot and identical restore | Required for supported local Study/Store; exact checkpoint/replay evidence must cover restored configured studies. |
| Incremental backup, arbitrary point-in-time restore, hourly/daily automation | Unqualified deployment capabilities. The supported core uses explicit full logical snapshots and supervised restore; label this limit in backup APIs/docs. A snapshot timestamp is not arbitrary PITR. Original stronger clauses stay visible in this inventory. |
| Operation metrics, structured logs, queue/error/resource visibility | Required local reports must retain units, scope and missing measurements; verify configured studies and documented status queries. |

| 100 studies / 50 workers, throughput and p99 targets | Unqualified capacity targets, not inferred from small tests. Record measured local capacity/latency and limitations; no remote or large load campaign is allocated. |
| Authentication, study roles, secrets, encryption and access audit | Retain exact local PostgreSQL/TLS/role evidence and document trusted-process boundaries. Application owner/collaborator/viewer policy, managed secrets and encryption at rest are unqualified deployment integrations, not supplied by TLS alone. |

| User GPU-hour/month quotas, dollar pricing/dashboard | Unqualified accounting integrations without a declared meter, pricing and period policy. Do not substitute raw elapsed seconds for GPU-hours or money. Local output must say what it actually measures. |

This reconciles the old deployment claims under D-LOCAL-OPERATIONS-SCOPE; it does not discard them from history or claim the software is production ready. A future deployment extension must register concrete remaining obligations and evidence before changing support status.

## Deferred-method and clause coverage

The 21 historical deferred rows have these explicit meanings: PBT/PB2/BG-PBT and large-parallel RL retain their finite local implementations; DEHB retains its owned finite method; selected GP robustness retains its narrow mathematical evidence; ifBO/pretrained-curve integration retains the failed feasibility and cancellation; neural transport retains the small trainable coupling fixture, with calibration/application effectiveness unestablished. The separate [coverage map](evidence/2026-10-12/bank-product-scope-01/coverage.json) keeps every original clause and legacy component reachable.

## Bounded execution

Work sequentially. Each implementation stage begins with a small counterexample/reference and a measured diagnostic, then focused affected tests, review, repair and next-stage refresh. Use the fixed [operations commands](../PROGRAM_OPERATIONS.md); each test process is capped at 300 seconds, one CPU and no GPU. Record total allocation before grouped execution. No full mutation, statistical comparison, installation download or external deployment is authorized merely by this design. Relevant existing qualification rules still apply to changed scientific source; this document-only reconciliation does not invalidate the accepted executable source.
