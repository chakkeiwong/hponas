Two source findings were reproduced with bounded diagnostics. The cost schedule
returns `[0, 0, .5, 1]` at counts `[0, 5, 10, 15]`, whereas the survey specifies
cost cooling from one toward zero over the budget. Existing tests encode the
reversed direction. The warm-start compatibility function accepts two otherwise
identical spaces with different log/linear transforms. These findings belong to
the existing T1-COST and T1-WARM implementation stages. Their phase prerequisites
remain explicit, and this review does not change the accepted Tier-0 source.

T1-COST previously had no acceptance campaign and a generic completion text
claiming evidence for “no campaign assigned.” It now has an explicit
`T1-COST/ACCEPTANCE-DESIGN` stage after method implementation and before the
Tier-1 protocol freeze. It must resolve its estimand, comparator, task scope,
error/power treatment and terminal consequence. It cannot reuse V04-T1 or add
an uncorrected seventh test to the six-entry Tier-1 family. This is a repair
to tracking an existing obligation, not an invented scientific threshold.

The new [exact cost review](evidence/2026-10-05/master-refresh-02/execution-01/exact-cost-bound.json)
also tightens the allocation diagnosis. Under the current 46-vector rule,
successful sizing requires all 46 vectors in both entries to be jointly good.
Every planned study must therefore have a resolved protected curve through
the final grid point. The independent search verifier then requires at least
the task's frozen search duration, including for a retained failed/trial-limit
prefix that reaches the endpoint. Expanding all 828 planned studies gives:

`46 × (4 + 2) × (2,820 + 5,160 + 3,660) / 3,600 = 892.4 hours`.

This is a lower bound on summed recorded search duration for a successfully
sized, fully resolved pilot under this exact design. It excludes protected
evaluation, startup, replay and overshoot. It is neither a universal lower
bound for the scientific problem nor a prediction of actual GPU utilization.
A futile or interrupted pilot can terminate much earlier.

The final-rank condition is also exact: equal weighting of three task outcomes
in `{-1, 0, 1}` and the frozen threshold `84/125` leave only `(1, 1, 1)` as a
qualifying vector. Two wins and a tie average `2/3`, which is smaller by
`2/375`. Thus each good vector needs a strict final protected win on every task
for each registered comparison; V04-T0 additionally needs every anytime
component. Enumeration, rational confirmation-event reconstruction and the
actual sizing API agree. These are conditional mathematical facts, not
measurements of optimizer superiority or probabilities of success.

Per-entry accounting is already repaired. Final-only V05 evaluation would
change its present all-grid loss semantics. Sequential fully evaluated-vector
futility would change the all-search-before-test chronology and can save only
work on unsuccessful pilots. Parallel execution can affect calendar time but
does not remove total work and changes the frozen runtime. Smaller search
budgets or a different sizing rule define a new prospective experiment and
require their own justification and evidence. None of these possibilities is
booked as implemented savings.

The 1,899.8-hour historical reservation is still a conditional scenario, not
an affordable recommendation or authorized allocation. The current evidence
does not supply an affordable complete pilot request. Mathematics cannot
establish an unknown optimizer advantage or guarantee power for arbitrarily
small positive effects. Scientific criteria therefore remain unchanged and
the allocation field remains empty.
