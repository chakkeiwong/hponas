## Goal and closure rule

Close all ten findings in the 17 October historical audit. Deliver reusable
HPO and coordinate NAS interfaces for universal-bank model families, using
independent small examples, objective numerical references, explicit failures,
recoverable execution and useful installed-package entry points. Preserve the
prior accepted source and failed research outcomes. No source change inherits
scientific acceptance from the prior package.

A clause closes only with behavior and evidence, or a precisely identified
existing exclusion/terminal result that is appropriate to that clause.
Unsupported implementation obligations remain open. A documentation change
cannot make an absent interface implemented. Research watchlists, ifBO's
failed/cancelled outcome, empirical usefulness and production-scale evidence
are reported distinctly. They cannot be converted into PASS by human acceptance.

## Specific design obligations

MO batch optimization is bounded by a finite candidate pool and maximum batch
size. Tiny known posteriors must demonstrate complementary joint choices.
Pending locations participate in posterior scoring and resume keeps RNG,
observation order and pending identities. Duplicate or exhausted domains have
explicit outcomes; returned batches cannot exceed the remaining trial budget.

Repeated streaming aggregates only matching declared fidelity across all
repetitions. No optimistic partial mean is observable. Failed/missing replicates
fail the candidate; cancellation, pause and resume retain actual and uncertain
work. Final evaluations cannot reach search or scheduler feedback. TPE learns
only comparable declared model-fidelity observations; low rungs remain stored.
Compatibility opt-out requires a persisted reason and cannot cross checkpoints
silently. Existing callers and tests are migrated explicitly, never by stack
inspection, hidden environment switches or automatic inferred reasons.

Population adapters own model, optimizer and checkpoint semantics. The engine
owns identity, lineage, budget, durable commits and selection/final roles.
Finite-MDP controllers and their qualification remain available; general
adapters must not merely wrap the same fixture under a new name.

Operations work stays on temporary local stores and owned processes. Migration
tests cover version transitions and rollback to verified backups. PITR requires
ordered committed events, integrity and boundary tests, not timestamped full
snapshots alone. Scheduling and alerts use a supplied clock/local sink; no email
or external messages. Role tests cover denied access before side effects.
Quotas state work units, price version and accounting period, never call CPU
seconds GPU-hours. Security integrations must state their trusted-host/key
boundary and fail closed when required support is unavailable. Large-scale
numbers require measurement and stay unqualified unless actually verified.

RGPE is separate from ranked initialization; source history identity and
target-only final roles are mandatory. Tiny arithmetic/posterior tests prove
the declared ensemble rule, not empirical transfer superiority. The historical
ifBO failure remains terminal; every watchlist method has an explicit outcome.

## Resources and approvals

Existing `hponas_ops.py` commands retain their exact forms. Additional operations
use the exact absolute `gap_ops.py` commands in `docs/PROGRAM_OPERATIONS.md`.
The reviewed operation manifest accepts named operations only, no shell,
arbitrary path, arbitrary pytest arguments, campaign allocation or external URL.
Each development process uses one CPU, one numerical thread, no GPU and a
300-second limit. A stage initially permits at most twelve development groups
and 3,600 seconds total; a failure is retained and repaired before retry.
At a boundary, review measured time and remaining tests before increasing the
stage allocation. A timeout does not justify blind repeated execution.

The grouped rules installer adds only the dedicated GAP command file in the
protected Codex rules directory, preserving existing global rules. It verifies
its pinned inputs, exact positive/negative matches and installed readback.
Managed approval remains authoritative; rules do not guarantee zero prompts.
The installation is the anticipated protected write. Ordinary workspace work
and the specified bounded local checks are already authorized. No new network
service, external message, deployment, destructive history or broad Python/bash
allow rule is requested. Separate-machine tests remain waived.

Scientific requalification is not silently allocated by development commands.
INTEGRATION-REVIEW must calculate its exact affected roster, dependency bindings,
resource envelope and guarded runner. If this needs resources beyond the
bounded development authority, that concrete allocation is a genuine blocker;
prepare all independently authorized work before requesting it. This unknown
cannot honestly be represented as a fully specified upfront campaign approval.

## Plan review checklist and execution rule

The retained review must establish: all G01–G10 covered; original subclauses
preserved; no circular dependencies; no fake equivalence between sequential and
joint search, snapshots and PITR, or ranked initialization and RGPE; evaluation
isolation and failure accounting; source qualification remains distinct;
operations are bounded; optional research is not reopened by implication;
the final independent audit is last and can reject completion.

After each phase, retain results, repair demonstrated faults, refresh the next
bounded plan and continue. Stop only for a real external blocker, explicit
user pause or objectively verified whole-workstream completion. Status updates
name the stage and any scope change. This workstream repairs inherited product
obligations; it does not change the bank-tool goal.
