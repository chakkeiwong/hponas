## Concrete amendment proposals

**P1 — claim identity.** Retain the register's exact 19 IDs and gates; rewrite conflicting markdown as new versions after approval. Preserve each previous version with hashes and keep all old results attached to their actual claim. Give random-versus-pathological PPO, GPU-capacity probes, Sobol-versus-random and warm-start diagnostics descriptive non-acceptance labels. No past result acquires a new PASS by renaming it.

**P2 — V03 population and operators.** Replace the 200-mutant cap with the complete population from a frozen list of shipped Tier 0 implementation paths. Resolve legacy GP/TPE and acquisition ownership explicitly before freezing; Tier 1 MO routines remain visible with separate deferred acceptance if not part of Tier 0. Include strings because error handling, dispatch labels, persistence keys and API text can be observable. Keep the current score definition, uncovered mutants in the denominator, and every numerical criterion in the table. Equivalent exclusions require an exact diff, behavioral argument, reviewer record and total <=5%; no extrapolation from a sample and no blanket exemption for message strings. Abnormal/build/tool outcomes remain classified, not fabricated kills. Four workers and six wall-clock hours are the current execution ceiling; expiry preserves evidence and is INCONCLUSIVE. The old `v03_protocol_amendment.md` is not adopted.

**P3 — statistical policy.** Retain the draft proposal of per-gate Holm family alpha 0.05, power 0.80 (0.90 for V04-T1/V08), task-cluster then paired-study-block resampling, 10,000 bootstrap draws, independent pilot of at least five per arm per side (V08 exception explicitly reviewed), 2,000 power simulations at each candidate sample size, sizing against the upper 80% variance bound, and no pilot reuse. These remain proposed until PI certification. Freeze range bounds before data; neither division by an observed mean nor a proxy variance estimate supplies the required normalized real-workload inference. Replication requires a predeclared owner, deadline, budget and stopping rule, not an automatic extra attempt after an unfavorable result.

**P4 — decision-bearing endpoints.** Recommend treating all required searchers, comparators and required endpoints within a single entry as an intersection-union claim: the entry passes only if every component clears its applicable threshold, with entry p-value the maximum valid component p-value. Apply Holm across entry p-values. This only licenses the conjunctive entry decision; optional per-searcher promotion requires a separately registered family. AUC, regret and time-to-recover cannot remain ambiguously “decision-bearing”: specify their hypothesis and threshold or explicitly amend them to descriptive status before data. Do not silently use the latter option. Use family-adjusted intervals consistently; nominal 95% intervals alone do not establish all claims in a six-entry family.

**P5 — unresolved scientific definitions.** V01 stochastic equivalence bands, V09 NI/superiority order, V10 regret threshold, V11b recovery-time threshold, V12 target non-attainment, and V13 simultaneous bands/multimodality thresholds need explicit rulings. V08 requires a fallback when V07 has never run; recommend BO+ASHA until a comparator has certified evidence, without pretending the deferred DEHB implementation already exists. These proposals are scope/design decisions under D-PROTOCOL/D-TIERS, not completed implementation.

## Execution and certification boundary

STAT-01 is complete when this reviewable identity/amendment package and exact inventory are preserved. That does **not** complete D-PROTOCOL or certify any experiment. The mandatory certification instruction is in `validation/protocols.json`, `policy.open_decisions[D5].procedure`: “PI certifies the final protocol set before any campaign spend.” General authorization to repair code is not that certification.

The next actions are already in the master: SPEC-01 implementation and PKG-01 installation verification can continue independently. STAT-02 needs the claim/policy ruling to prepare final task IDs, numerical scale bounds, endpoint-specific hypotheses, disjoint seed sets, measured pilot sizing and a reviewable capacity budget. Certification of that final design is required before confirmation. CAP-01 can inventory resources and existing runtime receipts now; no powered campaign size or available GPU allocation is inferred from installed hardware.

Acceptance must follow the final source/dependency/profile freeze. V03-03 and the statistical campaigns remain blocked until their particular prerequisites are met; the rest of the repair program does not stop at this document.
