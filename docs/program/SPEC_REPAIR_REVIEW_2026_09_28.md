# Specification repair review — SPEC-01

This is execution of an existing Tier 0 master-program item, not a change in product direction. Governing sources are the roadmap's Tier 0 section, the Bayesian chapter's dimension-scaled priors, the multifidelity chapter's PASHA decision and the model-free chapter's thin CMA-ES requirement. Verification receipts are under `evidence/2026-09-28/spec-01/`. Algorithm acceptance remains separate from these implementation checks.

## Changes and verification boundaries

**Main GP.** The production Matérn 5/2 kernel now uses BoTorch's `get_covar_module_with_dim_scaled_prior(..., use_rbf_kernel=False)`, including its published log-normal lengthscale prior and initialization. This makes the prior median proportional to the square root of normalized feature dimension. The existing ScaleKernel and qLogEI remain. The legacy GP already has a dimension-scaled Gamma prior; this repair does not claim those two prior distributions are identical. The independent BoTorch V01 arm is configured with the same declared main-model specification, without invoking the wrapper. Numerical tests inspect the model actually supplied to acquisition in 1, 4 and 16 dimensions, compare the covariance with the Matérn equation, and verify maximization/minimization and exclusion of failed observations. Real fitted-GP studies recover the exact uninterrupted proposal trace.

**PASHA.** The former implementation was budgeted ASHA, mislabeled “Promotion-based ASHA.” It is retained as `BudgetedASHAConfig`/`BudgetedASHAScheduler`, including its existing tests and checkpoint structure. `PASHAConfig`/`PASHAScheduler` now implement progressive resource allocation: start at the second fidelity, compare paired survivor ranks at adjacent top rungs, hold the cap while soft rankings agree, and open one higher rung on disagreement. Automatic tolerance uses the 90th percentile of differences for observed pairs whose ordering reverses and reverses back. A fixed nonnegative tolerance is also supported. Reports at unobserved fidelities are not imputed; sparse histories can leave the tolerance unchanged. A finite shared promotion budget is an optional, independent cap.

The soft-ranking criterion is compared against 144 frozen outputs from the actual Syne Tune 0.13.0 implementation, including ties and epsilon groups. The source reference, license header and wheel hash are retained. The reference dataset is Python source so it participates in the existing executable fingerprint. Tests also cover permanent versus transient reversals, incomplete pairs, cap expansion, paused-trial release, repeated/stale reports, JSON recovery, Study completion and event replay. These checks establish the progressive-cap component and local integration; they do not certify whole-scheduler parity with all Syne Tune scheduling/queue semantics. V01/V02 must define that final reference envelope.

A new integration check exposed a Study defect: it required an incumbent at the original `r_max`, so a successful stable PASHA run raised “No valid results found.” Incumbent selection now uses the scheduler's current maximum fidelity when supplied. It continues comparing candidates at one fidelity and does not treat a low-fidelity score as a full-budget result. A legacy budget-only scheduler checkpoint is rejected by progressive PASHA with an explicit instruction to use `BudgetedASHAScheduler`; it is not silently reinterpreted.

**CMA-ES.** `CMAESSearcher` wraps Optuna's maintained `CmaEsSampler` and cmaes 0.12 for unconditional continuous spaces. Existing normalized log/logit coordinate translation is reused; mixed or conditional spaces are rejected. Optuna owns covariance adaptation and generation bookkeeping. The optional `cmaes` extra supplies the dependencies without making them necessary for a base import. Independent vendor tests span 40 trials, both objective directions, serial/batched asks, failed evaluations, reversed completion order and JSON recovery with pending suggestions. A complete ask/tell ledger and vendor versions are required for exact recovery; incompatible versions/spaces or altered suggestions are rejected before replacing the live searcher. A Study run verifies direction and results. This is the thin wrap required by the roadmap; no performance/default recommendation is inferred from parity.

**Baseline contract and obsolete tests.** Study and GP reject zero-dimensional optimization explicitly; mutable empty space declarations can still be used while adding knobs. The prior empty-space skip is now an executing rejection test. Three skipped files for nonexistent custom GP/kernel/acquisition classes are preserved in `obsolete-tests/` and replaced with tests against the actual BoTorch path. The unadopted DRAFT class-naming policy remains a documented skip. These changes implement supported behavior, rather than introducing a second GP API merely to satisfy hypothetical tests.

## Review findings and remaining acceptance

The first focused run produced 160 passes and five failures. Three failures were a test's use of a nonexistent `LogNormalPrior.median` property (corrected to the distribution's 0.5 quantile); one incorrectly expected automatic noise tolerance to behave like fixed zero tolerance (the fixed-tolerance and automatic-noise cases are now separate); one was the real Study incumbent defect described above. The failed log remains preserved. Subsequent focused runs passed 107 tests and 26 GP tests; a 26-test PASHA/evidence preflight also passed. The full-suite receipt is recorded separately after execution.

V03's required module inventory now includes the new CMA-ES module, and its critical function list includes progressive ranking/tolerance, budgeted promotion, and CMA-ES ask/observe/recovery. This prevents the new implementation from silently escaping the existing module and critical-survivor requirements. It does not settle the broader V03 operator/population decision or exclude any mutant. CI installs the optional CMA-ES dependencies when testing that declared capability.

The first broad suite completed with 1,242 passes, one documented skip and four failures. Three seed/argument validation fixtures supplied a raw list instead of either supported SearchSpace API; the valid fixtures now construct the real space. The fourth fixture took a checkpoint after eight suggestions and truncated only its history to five, retaining future RNG/suggestion/trial state. It now captures the complete checkpoint at the actual boundary and requires exact equality of all three resumed proposals instead of a 0.1 tolerance on only two coordinates/trials. The original broad failure is preserved; final focused verification and any later broad result are separate receipts.

No performance threshold, gate PASS or scientific signature is changed. Full mutation acceptance must run on the final packaged source after protocol reconciliation. V01/V02 need the agreed full task/scheduler/wrapper matrix; the current narrow recipes remain narrower evidence. The transition after this implementation verification is PKG-01, already in the master program. Remaining statistical decisions do not block that installation work.
