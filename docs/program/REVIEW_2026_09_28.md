## Review of the proposed controls

The work register carries owner roles, dependencies, separate implementation state, done-when conditions, next action, compute limits, source/test paths and evidence references. It cannot create authority by declaring a signature. Current user authorization is recorded only for the work actually requested.

Status generation never promotes a phase from a Git tag or a narrative checkbox. The program checker validates immutable receipt bindings and freshness; it does not rerun scientific experiments or grant certification. Full V16/gate recomputation remains required. CI must accept a truthful BLOCKED program and reject misleading status.

Negative verification must cover dropped/duplicate decisions, renamed protocol claims, altered rules, dependency cycles, unresolved prerequisites, missing/forged receipt fields, artifact tampering, stale source evidence and edited generated output. Test fixtures must not rely on a live Ray cluster or silently grant a gate PASS.
